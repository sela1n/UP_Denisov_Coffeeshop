## О проекте

WPF-приложение для учёта продаж сети кофеен. Сотрудники и администраторы оформляют продажи позиций меню,
позиции сгруппированы по категориям. Данные хранятся в Microsoft SQL Server (три связанные таблицы),
доступ к ним — через Entity Framework (Database First).

## Возможности

- Авторизация и регистрация с ролями **Admin** и **User**; пароли хранятся как SHA1-хэши.
- Проверка пароля (не менее 6 символов, латиница, хотя бы одна цифра).
- После 3 неверных попыток входа — капча (копирование и вставка запрещены).
- Смена пароля.
- Страница пользователя: карточки сотрудников с фото, поиск по ФИО, сортировка, фильтр «Только администраторы».
- Страница администратора: таблицы пользователей, категорий и продаж; добавление, редактирование, каскадное удаление с подтверждением.
- Диаграммы продаж по категориям (Chart) с выбором сотрудника и типа диаграммы.
- Экспорт отчётов в **Word** (.docx и .pdf) и **Excel** (.xlsx): таблицы, колонтитулы, максимальная продажа — красным, минимальная — зелёным.
- Единый словарь стилей (шрифт Open Sans), две темы оформления, выбор темы сохраняется между запусками.
- Плейсхолдеры, всплывающие подсказки, динамические заголовки страниц, маски ввода, запрос подтверждения при выходе и удалении.

## База данных

Три таблицы, связи «один ко многим» с каскадным удалением (`ON DELETE CASCADE`):

| Таблица | Поля | Назначение |
|---|---|---|
| `User` | ID, Login, Password, Role, FIO, Photo | пользователи, сотрудники, администраторы |
| `Category` | ID, Name | категории позиций меню |
| `Payment` | ID, UserID → User, CategoryID → Category, Date, Name, Num, Price | продажи (чеки) |

В скрипте есть тестовые данные: 5 пользователей, 5 категорий, 28 продаж.

## Запуск

**Требуется:** Windows, Visual Studio 2019/2022 (разработка классических приложений .NET), Microsoft SQL Server (Express/LocalDB) и SSMS.
Для экспорта в Word и Excel нужен установленный Microsoft Office.

1. Откройте `db/schema.sql` в SSMS, замените `Surname` на фамилию латиницей (Ctrl+H → «Заменить все») и выполните скрипт (F5).
   База `DB_<Фамилия>_CoffeeShop` создаётся заново вместе с тестовыми данными.
2. Откройте решение `<ИмяПроекта>.sln` в Visual Studio, дождитесь восстановления NuGet-пакетов (EntityFramework 6).
3. В `App.config` проверьте строку подключения `Entities`: имя сервера (`data source`) и базу (`initial catalog=DB_<Фамилия>_CoffeeShop`).
4. Соберите и запустите проект (F5).

## Особенности реализации и ограничения

- Хеширование SHA1 без «соли» — вариант учебного задания; в промышленной системе применяют bcrypt, PBKDF2 или Argon2 с солью.
- Счётчик неверных попыток входа хранится в памяти страницы и сбрасывается при перезапуске приложения.
- При регистрации роль выбирается вручную (так задумано в учебном проекте); в реальной системе роль назначает администратор.
- Фотографии в `res/photos` — тестовые, персональные данные в репозиторий не загружаются.
